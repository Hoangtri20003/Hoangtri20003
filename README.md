### 🏗️ Livi — how it's built

One shop runs a **booking kiosk** and a **photo kiosk per booth**; they never talk to each other directly — everything goes through the API. A guest books and pays at the booking kiosk, takes the printed QR ticket to a booth, scans it and shoots.

```mermaid
flowchart LR
  subgraph Shop["🏪 In the shop"]
    direction TB
    CASH["💵 Bill acceptor<br/>RS232"] --> BK["🧾 Booking kiosk<br/>Electron · Next.js"]
    BK --> TP["🖨️ Thermal printer<br/>ESC/POS"]
    TP -. "QR ticket" .-> QR["🔍 QR scanner<br/>USB HID"]
    QR --> PK["📸 Photo kiosk<br/>Electron · Next.js"]
    CAM["📷 Canon camera<br/>EDSDK"] --> PK
    PK --> DNP["🖼️ DNP printer<br/>Hot Folder Print"]
  end
  subgraph Cloud["☁️ Cloud"]
    direction TB
    API["⚙️ API<br/>NestJS · Railway"]
    ADMIN["🖥️ Admin web<br/>Next.js · Vercel"] <--> API
    API --> DB[("🍃 MongoDB Atlas")]
    API --> R2[("🪣 Cloudflare R2<br/>photos")]
    API --> REDIS[("⚡ Redis cache")]
  end
  BK <-->|"book · pay"| API
  PK <-->|"check in · upload"| API
  API <-->|"bank transfer"| PAY["💳 payOS"]
  API -->|"receipts"| MAIL["✉️ Brevo"]
```
